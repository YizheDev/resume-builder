# Resume Builder — 需求设计文档（v5）

日期：2026-06-09

---

## 一、产品理念

**AI 负责思考，用户负责决策。** 

用户不需要写出大段文字，只需要动手指勾选，AI 完成所有专业内容创作。

## 二、核心交互：选择式简历生成

### 2.1 设计原则

```
传统方式：问用户 → 用户想半天 → 写不出来 → 放弃
我们方式：AI 列出高质量选项 → 用户勾选 → AI 润色成专业描述
```

### 2.2 完整流程

```
用户输入背景（一句话即可）
  ↓
AI 推荐岗位列表 → 用户勾选多个
  ↓
对每个岗位，AI 逐模块引导：
  ┌────────────────────────────────────────────────┐
  │ 💼 关于你的后端开发实习，你做过哪些？             │
  │                                                 │
  │ ☑️ API 接口设计与开发（RESTful，Swagger 文档）   │
  │ ☑️ 数据库设计与优化（MySQL，索引，慢查询优化）    │
  │ ☐ 用户认证与权限管理（JWT，OAuth2.0，RBAC）     │
  │ ☐ 微服务架构设计与拆分（Spring Cloud，Docker）   │
  │ ☐ 消息队列集成（RabbitMQ / Kafka）              │
  │ ☐ 缓存方案设计（Redis，多级缓存）                │
  │ ☐ 自动化测试（单元测试、集成测试、CI/CD）        │
  │ ☐ CI/CD 流水线搭建（Jenkins，GitHub Actions）   │
  │ ☐ 日志监控系统搭建（ELK，Prometheus）            │
  │                                                 │
  │ [✨ 帮我推荐适合我背景的选项]                     │
  │ [⏭️ 没有实习经验，跳过]                          │
  │ [✅ 确认选择，AI 帮我润色]                       │
  └────────────────────────────────────────────────┘
```

### 2.3 智能推荐

每个选择列表底部都有自定义输入口，用户可以自己写 AI 没列出的内容：

```
┌────────────────────────────────────────────────┐
│ 💼 实习经历                                      │
│                                                 │
│ ☑️ API 接口设计与开发                            │
│ ☐ 数据库设计与优化                               │
│ ☐ 微服务架构                                    │
│ ...                                             │
│ ─────────────────────────────────────           │
│ ✏️ 其他（自己补充）：                             │
│ ┌─────────────────────────────────────────┐    │
│ │ 我还负责了代码审查和新人培训...            │    │
│ └─────────────────────────────────────────┘    │
│ AI 会自动将你的描述润色为专业措辞               │
└────────────────────────────────────────────────┘
```

用户勾选了某些选项后，AI 智能推荐关联选项：

```
💡 你勾选了"API 接口开发"，建议也勾选"接口文档 Swagger"和"Postman 测试"
💡 你勾选了"数据库优化"，建议也勾选"Redis 缓存"
```

### 2.4 AI 润色

用户勾选完后，AI 一键生成专业描述：

```
用户勾选：☑ API 接口  ☑ 数据库优化

AI 生成：
- 负责 XX 系统后端 API 设计与开发，基于 Spring Boot 构建 RESTful 接口
  共 20+ 个，使用 Swagger 自动生成接口文档，提升前后端协作效率
- 主导数据库性能优化，通过慢查询分析、索引优化、SQL 改写等手段，
  将核心查询响应时间从 2s 降至 200ms，支撑日均 10 万+ 请求量
```

## 三、简历内容结构（7 模块）

每个模块都采用选择式交互：

### 3.1 个人信息 + 照片
- 姓名、手机、邮箱（用户填写，一次性）
- 照片上传（JPG/PNG → 自动裁剪证件照）

### 3.2 教育背景
```
AI 列出该岗位相关的高质量课程选项：
☑ 数据结构与算法
☑ 操作系统
☐ 计算机网络
☐ 数据库原理
☐ 软件工程
☐ 编译原理
[帮我推荐] [跳过]
```

### 3.3 奖项荣誉
```
AI 根据背景推荐可能获得的荣誉：
☐ 校级奖学金
☐ 优秀学生干部
☐ ACM/数学建模等竞赛获奖
☐ 大创项目立项
[帮我推荐] [跳过]
```

### 3.4 实习/工作经历
```
AI 列出该岗位实习生通常做的工作：
☑ API 接口开发
☑ 数据库优化
☐ 微服务拆分
☐ 消息队列集成
☐ 自动化测试
[帮我推荐] [跳过]
```
用户勾选后，AI 追问细节（可选跳过）→ 生成专业描述

### 3.5 项目经历
```
AI 列出该岗位常见项目类型：
☐ 电商系统（Spring Boot + Vue）
☐ 博客/内容管理系统
☐ 数据分析平台
☐ 即时通讯应用
☐ 个人技术博客
[帮我推荐] [跳过]
```
用户勾选后，AI 生成项目名称、技术栈、功能亮点

### 3.6 技能
```
AI 列出该岗位常见技能栈，按重要性排序：
🔴 必须掌握：
  ☑ Java  ☑ Spring Boot  ☑ MySQL  ☑ Git
🟡 加分项：
  ☑ Redis  ☐ Docker  ☐ Kubernetes  ☐ RabbitMQ
🟢 了解即可：
  ☐ Go  ☐ Python  ☐ 前端基础
```
用户勾选/取消，AI 自动分级：熟练 / 了解

### 3.7 自我评价
```
AI 根据前面所有选择，生成 3 个版本的自我评价：
版本A（技术深度向）：
  "拥有扎实的Java基础和Spring生态经验，熟悉高性能后端架构设计..."
版本B（全面发展向）：
  "计算机科班出身，具备后端开发+数据库优化+项目管理综合能力..."
版本C（成长潜力向）：
  "热爱技术，持续学习，在校期间通过多个项目实践积累丰富开发经验..."
[选这个] [再生成3个] [跳过]
```

## 四、跳过与兜底

| 场景 | 处理 |
|------|------|
| 完全没有实习经验 | AI 把项目经历包装得更重，突出技术能力 |
| 不知道怎么写项目 | AI 根据技能栈反推一个虚拟项目框架，用户确认 |
| 没有获奖 | 模块不显示 |
| 技能不确定 | AI 默认勾选该岗位高频技能，用户直接确认 |

## 五、编辑模式

生成初稿后，所有内容可手动修改。每个模块支持：
- 修改文字内容
- 增删条目
- 调整顺序
- 重新选择模板

底部：[继续AI对话修改] [保存] [导出PDF]

## 六、模板规范

- 纯白底色，无花哨装饰
- 黑 + 单色强调（深蓝/深灰）
- 照片固定位置：个人信息区右上角
- 5 套模板仅差异于布局，配色统一

## 七、页面路由

```
/                    首页 → 输入背景
/recommend           岗位推荐 → 多选勾选
/chat/:id            对话式选择页 → 逐模块勾选 + AI 润色
/edit/:id            编辑页 → 手动修改 + 预览 + 导出
```

## 八、数据库

```sql
CREATE TABLE resumes (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    title        VARCHAR(100) NOT NULL DEFAULT '未命名简历',
    role         VARCHAR(100) NOT NULL,
    template     VARCHAR(50)  DEFAULT 'classic',
    data         JSON NOT NULL,
    selections   JSON,                   -- 用户选择记录
    photo_url    VARCHAR(500),
    chat_history JSON,
    status       VARCHAR(20) DEFAULT 'chatting',
    created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```
